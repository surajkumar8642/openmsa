# Governance

OpenMSA is maintained as an open community project.

## Maintainers

- One maintainer coordinates triage and release planning.
- Maintainers review and merge PRs after at least one positive technical review for major architectural changes.

## Change process

1. Proposal in issue or PR
2. Review of security and compatibility impact
3. Merge when tests pass and intent aligns with global contract

## Release process

- Version tags are published when interfaces are stable.
- Breaking changes are documented in `CHANGELOG.md`.
- GitHub Discussions/Issues are preferred for proposals; PRs for implementation.
